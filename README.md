# MedLens

Експериментальна інтерактивна карта пацієнта з HematoBoard: рухома 2D-лінза, реєстр об’єктів, клінічні дати й точні структуровані джерела.

## Перегляд

[Відкрити MedLens](https://esannikov.github.io/medlens/).

Після оновлення07.09.2026:

- [Порівняти варіанти поруч](https://esannikov.github.io/medlens/?lens=lab)
- [Дві пов’язані лінзи](https://esannikov.github.io/medlens/?lens=dual)
- [Перегрупування записів](https://esannikov.github.io/medlens/?lens=regroup)
- [Незмінний контрольний варіант](https://esannikov.github.io/medlens/control/)

У лабораторії дві незалежні панелі. Кожна має власний фокус і відбір; для
зіставлення встановіть однакові умови або відкрийте варіант окремо. Контроль
зібраний із commit`cb3fb4d`, використовує той самий знеособлений JSON і не
оновлюється разом з основною лінзою.

Перетягніть гілку до центра: підписи й вузли збільшуються, відкриваючи вміст. Натисніть на підпис для читання конкретного запису. «Граф + таблиця» показує повний реєстр. «Час» відбирає записи до обраної дати; недатовані записи можна приховати окремо. Це відбір поточної ревізії, а не реконструкція знань у минулому. Гіпотези не підключені.

За рішенням користувача від 06.09.2026, якщо власна або пов’язана клінічна дата відсутня, MedLens використовує явну дату видачі дослідження для показу, пошуку й часового відбору. Вона позначена «видано»; результати та матеріали без власної дати показуються «за датою видачі дослідження». Клінічні дати залишаються пріоритетними. Реєстрація й замовлення не підміняють дату видачі; суперечливі або невалідні дати не використовуються. Вихідний Patient Graph не змінюється.

Нерухоме внутрішнє кільце з м’якою світлотінню показує зону збільшення. Розмір підписів плавно змінюється приблизно від 12 до 21 px; довгі назви додатково підлаштовуються до ширини. Дослідження та короткі знахідки показуються повністю, текстові значення переносяться без обрізання. Довгі описи мають нейтральну навігаційну назву зі стрілкою; натискання відкриває повний незмінений текст. Це не автоматичний клінічний підсумок. Короткі результати з’являються до входу у внутрішню зону. Підписи зберігають сусідство з вузлом і не перекидаються між незалежними слотами на кожному кадрі. При тісному зіткненні з вузлами окремий підпис може тимчасово ховатися; назва фокуса лишається над картою.

Активна гілка отримує кольоровий акцент; короткий блік на внутрішньому ободі реагує лише на перетягування. Системне зменшення руху вимикає блік. Під лінзою можна вибрати тонкі, збалансовані або виразні лінії. Їхня товщина позначає навігацію, а не клінічну важливість чи достовірність.

[Наукова основа лінзи та подібні реалізації](docs/LENS_FOUNDATIONS.md): focus+context, гіперболічне дерево, диск Пуанкаре й семантичне масштабування.

Підписи лінзи, значення й дати використовують вузьку моноширинну Iosevka. Три локальні накреслення завантажуються перед розкладкою підписів; за недоступності шрифту вимірювання й показ узгоджено переходять на системний моноширинний шрифт. Довгі тексти у панелі читання залишаються зі звичайним шрифтом інтерфейсу. [Версія, ліцензія та склад шрифту](public/fonts/iosevka/README.md).

## Дані

Знеособлений CASE024 має дозвіл на зовнішню публікацію. Це фіксована read-only проєкція схваленої ревізії Patient Graph, не нове джерело клінічної істини. Вона містить 185 об’єктів, 148 результатів і 306 структурних зв’язків. Оригінальні PDF, зображення, приватні файли, локальні шляхи й сесійні ключі не публікуються. Адреса джерела відкриває лише знеособлений структурований текст.

Базовий публічний пакет: [HematoBoard CASE024](https://esannikov.github.io/hematoboard/?case=case024). Хеші та склад цієї статичної проєкції: [publication.json](public/data/publication.json). Дати, значення, одиниці, невизначеність і статуси перевірки збережено; технічна перевірка інтерфейсу не означає клінічної валідації або лікарського прийняття. Демонстрація не призначена для ухвалення клінічних рішень.

Застосунок не має входу, завантаження документів, аналітики відвідувань чи запису змін. Дані статичного сайту загальнодоступні; `noindex` не є захистом доступу.

## Локальна розробка

Node.js 24; `npm ci`, `npm test`, `npm run dev`. Для перевірки саме статичної збірки: `npm run build`, потім `npm run preview`. Відкриття HTML через `file://` не підтримується.

React + TypeScript + SVG; власна реалізація гіперболічного фокуса. Three.js та попередні 3D-прототипи не входять до MedLens. Зміна даних потребує нового схваленого джерельного експорту; не редагуйте клінічні значення вручну.

Офлайн-експортер `scripts/export-publication.mjs` приймає явні шляхи до Graph, CaseScope і схваленого public package та перевіряє точні SHA-256 вхідних файлів до читання клінічних полів. Ці приватні входи не потрібні для запуску або збірки MedLens і не зберігаються в репозиторії.

GitHub Actions запускає тести й збірку перед публікацією `dist` на GitHub Pages. Відносні адреси підтримують розміщення в `/medlens/` без сервера застосунку.

## Нові способи роботи

- Лічильник під лінзою показує, скільки результатів активної гілки мають підпис.
  Кнопка відкриває повний список, включно з усіма прихованими підписами.
- «Вигляд»: масштаб тексту100/115/130%, безпечне унормування запису одиниць,
  додаткові структурні зв’язки. Значення не перераховуються; невідома
  відповідність одиниць не підміняє оригінал.
- «Перейти» та клавіші ←/→/↑/↓: батько, дочірній та сусідні записи; Enter
  відкриває читання. Навігація клавішами не перехоплюється панеллю читання.
- Пошук відкриває список біля поля. У «Уточнити пошук» є тип, розділ, період
  і підстава дати. Це прозорий структурований відбір, не медична генерація.
- Часове порівняння показує A∪B. Записи лише в A читаються разом із джерелами
  без скидання B. Порівнюється склад поточної ревізії, не фізіологічний стан.
- «Місця»: явне локальне збереження фокуса, відкритого запису, дат, масштабу та
  ревізії. Можна відновити місце чи завантажити маршрут JSON. Клінічний текст
  та пошукові фрази у закладки не записуються; зовнішнього сервісу немає.
- У записі є статуси полів, можливі повтори зі спільного джерела та список
  однойменних показників. Числова серія потребує однакового визначеного методу,
  матеріалу, одиниці та клінічних дат. Якщо підтвердження бракує, список лишається,
  але фізіологічний графік не будується. Між вимірюваннями немає інтерполяції.

У великих змінах збережено експериментальний статус: дві пов’язані лінзи —
самостійні фокуси, а не нова спільна біфокальна геометрія; перегрупування
використовує атрибути пакета. Анатомічний пошук показує лише текстові згадки,
не підтверджену локалізацію чи цифрового двійника тіла. Гіпотези в цьому наборі
відсутні й не вигадуються. Клінічне дослідження користі потребує окремого запуску.
